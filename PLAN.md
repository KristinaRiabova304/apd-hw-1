# План

## Що потрібно зробити

Реалізувати потрібну поведінку у файлі Sources/StudyPlanner/StudyPlanner.swift.
Публічний API та готові публічні тести змінювати не можна.

Треба зробити:

Перевірку StudyItem, тобто порожню назву, невірну кількість хвилин та
правильний порядок перевірок, спершу назва, потім хвилини.

Правильне декодування, тобто StudyItem з перевіркою, StudyPlan через ключ
items, та StudyPlan через масив JSON без ключа.

Роботу з дублями та сортуванням, тобто повідомлення про перший дубль id та
сортування спочатку за назвою, потім за id.

Запити та завершення завдань, тобто пошук за категорією, підрахунок хвилин
незавершених завдань, помилку для невідомого id та можливість повторно
викликати завершення без помилки.

Додаткове завдання importMerging, тобто відхилення дублів id у нових
завданнях без зміни плану, заміну існуючих завдань на їхньому місці, додавання
нових завдань у кінець за зростанням id, та збереження плану незмінним якщо
сталася помилка.

## Критерії готовності

Порожня назва після видалення пробілів викликає помилку blankTitle. Ця
перевірка йде першою, тому якщо назва порожня і хвилини невірні одночасно,
буде саме помилка blankTitle.

Невірна кількість хвилин, тобто нуль або менше, викликає помилку
nonPositiveEstimatedMinutes.

StudyPlan не створюється, якщо серед завдань є однакові id. Повідомляється
саме перший дубль, який зустрічається під час перевірки списку.

Готовий план зберігає завдання відсортованими спочатку за назвою, потім за id.

Декодування StudyItem через JSONDecoder виконує ту саму перевірку, що й
звичайне створення завдання.

Декодування StudyPlan через ключ items застосовує ті самі правила про дублі
та сортування.

StudyPlan.decode(from:) вміє прочитати масив JSON без обгортки у вигляді
об'єкта.

items(in:) повертає завдання потрібної категорії у збереженому порядку.

incompleteMinutes() рахує суму хвилин лише для незавершених завдань.

markCompleted(id:) викликає помилку unknownID для невідомого id, а повторний
виклик для вже завершеного завдання не викликає помилку.

importMerging перевіряє дублі id серед нових завдань першим кроком і не
змінює план, якщо дублі знайдені. Існуючі id замінюються на своєму місці.
Нові id додаються в кінець списку, відсортовані за зростанням. План
змінюється лише після успішної перевірки всіх умов.

## Кроки реалізації

Спочатку написана перевірка в StudyItem, назва перевіряється першою, потім
хвилини.

Далі додано декодування StudyItem через власний init(from decoder:), яке
викликає ту саму перевірку, що й звичайне створення. Поле isCompleted
змінено з private на fileprivate, щоб StudyPlan міг його змінювати в межах
одного файлу без додавання нового публічного методу.

Потім написано StudyPlan.init(items:), який спочатку шукає дублі id, а потім
сортує завдання за назвою і за id.

Додано декодування StudyPlan через ключ items та окремий метод decode(from:)
для масиву JSON без обгортки. Обидва варіанти використовують ту саму
перевірку через init(items:).

Написано методи items(in:), incompleteMinutes() та markCompleted(id:).

Написано importMerging, який спочатку перевіряє дублі серед нових завдань,
потім готує новий список окремо від поточного, замінює існуючі завдання та
додає нові в кінець за зростанням id, і лише тоді зберігає результат у items.

Додано дванадцять власних тестів у файл
Tests/StudyPlannerTests/StudyPlannerStudentTests.swift, які перевіряють усі
пункти вище, включно з додатковим завданням.

## Ризики та складні місця

Довелося змінити isCompleted з private на fileprivate, щоб StudyPlan міг
завершувати завдання. Це не змінює публічний API, бо цей метод запису й так
не був публічним.

У importMerging не зовсім зрозуміло, чи потрібно пересортовувати весь список
за назвою після об'єднання. Обрано варіант без повторного сортування за
назвою, бо умова каже, що існуючі завдання лишаються на своєму місці, а нові
додаються в кінець за зростанням id.

Перевірка порожньої назви прибирає лише пробіли та переноси рядків, як у
готовому тесті testBlankTitleIsRejected.

У importMerging дублем вважаються лише повторення id серед нових завдань.
Якщо новий id збігається з уже існуючим у плані, це вважається заміною, а не
помилкою.
